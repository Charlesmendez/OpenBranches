# PR checks and submitted reviews

People & PRs now shows compact check results and submitted-review counts. Expanding a card reveals named checks, commit statuses, review authors, recorded review states, the reviewed commit, and observation time. The branch inspector reuses the same component. **Checks need attention** filters open PRs with recent reported failures on their observed head commit; person, project, search, and tool filters continue to combine with it.

These are observed results, not a merge-readiness calculation. No required-check policy, branch protection, ruleset, code-owner rule, approval quorum, or merge queue is evaluated. A recorded approval on another commit is labeled as such. Dismissed reviews remain dismissed. The count describes submitted review events, not distinct approving people. Requested reviewers retain their separate role in the people roster; submitting a review does not establish company membership or branch ownership.

## Sources and boundaries

The reader uses GitHub's read-only [check runs for a Git reference](https://docs.github.com/en/rest/checks/runs#list-check-runs-for-a-git-reference), [combined commit statuses](https://docs.github.com/en/rest/commits/statuses#get-the-combined-status-for-a-specific-reference), and [submitted PR reviews](https://docs.github.com/en/rest/pulls/reviews#list-reviews-for-a-pull-request) endpoints. Checks and statuses are requested from the PR's base repository using the exact observed head SHA. Returned commit identities must match. A new PR head immediately drops old signal evidence, even when the next read has no remaining budget.

This covers checks returned for the PR head in that repository. It does not include every fork-local, synthetic merge-commit, merge-group, deployment, or external CI source. GitHub's check-run endpoint also limits its underlying check-suite window to the latest 1,000 suites. “Passed” describes the returned check/status results; the UI never says all required checks passed. No results, incomplete coverage, neutral/skipped outcomes, unknown provider states, permission errors, and stale observations cannot produce a passing summary.

Check names, IDs, normalized state, and short result codes are retained. Review IDs, actor identity, state, commit SHA, and submitted time are retained. Review bodies, pending/unsubmitted review drafts, check output, annotations, logs, profile fields, and arbitrary response URLs are discarded. The existing fixed-origin HTTP transport provides timeouts, redirect rejection, credential handling, and rate-limit backoff. Nothing is posted to GitHub.

Public repositories can be read without authentication. A registered GitHub App needs **Checks (read)** and **Commit statuses (read)** in addition to the existing Metadata, Contents, and Pull requests read permissions. Missing permissions remain visible as unavailable evidence; they do not erase PR metadata or silently become success.

## Refresh and storage

The desktop service refreshes GitHub sources every two minutes while running. Check/review reads share a separate global limit of six request attempts and twenty seconds of elapsed request time per refresh. It stops starting requests after that budget; an in-flight request retains the HTTP layer's fifteen-second timeout. At least three request slots are needed to start another PR. Each of the three endpoints is limited to two pages of 100. PRs and repositories rotate to prevent one source monopolizing every refresh. Each PR is attempted at most once per ten minutes unless its head changes. Large workspaces and anonymous rate limits can make coverage substantially slower; this is not a real-time GitHub event stream.

Only open PRs receive new signal reads. Existing observations can accompany recently closed history. Unread work is visited before older attempted work. An attempt time is separate from the successful observation time. Errors keep saved timestamps, and independently successful endpoints can update without refreshing failed evidence. Partial positive failures can appear in the attention filter, but partial passing data never becomes a passing summary. PR source failures and retained PR state are excluded from that filter.

The cache retains aggregate counts plus at most 30 check rows and 30 submitted review rows for each of the 100 most recently attempted PRs per GitHub source. Check details put failures first; review details show the newest events within the observed pagination window. Counts still describe every decoded record within that window. The UI pages detail rows ten at a time and states when details or source pages are omitted. Evicted detail records retain their attempt times so queue ordering survives restarts. Existing overall source-cache limits still apply.

Multiple local clones or remotes share PR identity in the view. The newest PR metadata is chosen independently from exact-head signal observations, so a later listing without a signal read does not erase useful evidence from another clone. Newer signal attempts and source failures remain visible. Project removal and disconnect reuse the existing service generation checks and transactional cache pruning; a late read cannot restore removed metadata.

## Verification and remaining work

Automated checks cover metadata exclusion, exact commits, review dismissals and drafts, non-passing outcomes, missing and stale evidence, failed-check filters, shared request and elapsed-time budgets, partial paging, detail limits, cancellation, endpoint errors, cache consistency, clone merging, changed heads, and preserved inputs. The complete suite passes 183 tests across 18 files at this milestone. Type checking and production builds also pass.

A live anonymous read against the public OpenBranches draft PR returned matching head evidence with complete empty check and review lists. Browser checks at 1280 × 820 verified the failure filter, expansion, keyboard activation, and saved-result labels; the console contained no warnings or errors. The rebuilt Mac app loaded the shared component through its production protocol, displayed the same real PR evidence in the inspector and People & PRs, and preserved both monitored projects. Fictional examples include failures, pending, passing, neutral/skipped, partial, stale, absent, dismissed, and different-commit review evidence.

This is the personal GitHub evidence layer. Company membership, the authenticated team service, opted-in local sharing, streamed team updates, company alert snooze/dismissal, and two-member/device verification remain in the [team contract](TEAM_WORKSPACES.md). Broader authenticated/private-repository, CI-provider, native, and accessibility checks remain release work. The app still cannot close, approve, merge, rerun, or delete anything on GitHub.
