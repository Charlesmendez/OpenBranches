# First release: scope and acceptance

The goal is a polished, simple, open-source Mac desktop app that explains where coding-agent work lives and how it relates to develop/dev/main/master, even across hundreds of branches. The user expanded the scope to automatic projects, multiple coding agents, and company workspaces with GitHub plus opted-in local work. This scope must not be reduced to the existing demo or local-only prototype. See [team workspaces](TEAM_WORKSPACES.md).

## Product contract

- Electron desktop application for Apple Silicon and Intel, with a signed/notarized drag-to-Applications release.
- Local Git repositories and their worktrees, plus published GitHub branches and pull requests. Team workspaces must also include unpublished local work voluntarily shared by teammates' connected devices. Unpublished cloud tasks need an explicit supported source; do not imply they are visible by default.
- Discover saved coding-tool projects automatically, provide search across all projects, and allow removal with persistent exclusions that prevent automatic re-addition.
- Support multiple coding tools with evidence-based icons and optional model identity. Codex, Claude Code, Grok integrations, and extensible provider adapters are required; unknown or unsupported sources must be labeled accurately.
- Add personal/team separation, people/project/agent filters, PR and review alerts, an optional open-source shared service, authenticated device pairing, and explicit project sharing. Verify access isolation, revocation, unsharing, stale sources, and preservation of personal data across at least two real member devices.
- Dark graphite interface with workspace overview, grouped map, expandable groups, searchable/virtualized inventory, focused inspector, activity, and an evidence-backed review inbox. The demo contains fictional data only.
- Automatic local updates and periodic remote refresh, with source provenance, freshness, partial results, and offline state visible.
- Optional Codex integration through an installed, signed-in client. Link tasks using explicit evidence; distinguish verified links from possible associations. Core Git inspection must work without Codex or AI.
- Needs attention uses deterministic Git and provider evidence, one row per branch, and bounded review queues. A user can send one row or a multi-selection to an installed Codex, Claude, or Cursor client for a read-only investigation and concrete proposal.
- Every handoff shows the exact branch groups, evidence, destination, and prompt before launch. Selections spanning repositories become separate tasks. Repository content and task text remain untrusted data, never instructions to OpenBranches.
- Read-only v1. Suggestions do not execute merge, rebase, push, deletion, cleanup, or worktree removal. Opening folders, tasks, and PRs is allowed.
- MIT, modular code, no repeated business logic, meaningful tests, second-pass review, and a PR to develop.

## Remaining implementation and release work

The latest requested work is tracked in `docs/TEAM_WORKSPACES.md`. The team browser puts a bounded, prioritized company queue ahead of the full inventory. It combines current failing checks, review requests, quiet drafts, exact merged-branch copies, local-only branches, and apparently forgotten shared work into one finding per PR or branch. It ranks work for the signed-in member and persists private snooze, dismiss, restore, and bulk choices against evidence revisions. Local rows open the exact person/project/device/branch in `Live & local`. PRs remain visible independently of remote-branch presence, exact deleted-branch associations are preserved, and open PRs have their own listing. Bounded exact-commit lookup now recovers older closed or merged PRs that fall outside the recent listing.

1. Finish source semantics: combined native verification and broader watch/restart behavior. The title bar now summarizes current, refreshing, delayed, partial, and disabled state independently for Local Git, GitHub, live activity, and task history. Verified running and waiting sessions are promoted into a bounded cross-project rail and the selected project's map, with exact navigation, coding-tool identity, and compact development/stable target status. Project cards retain broader dirty/recent/current-checkout context. Standard targets, a verified symbolic remote-default fallback, and an explicit no-target map/inventory/inspector state are implemented. Branch-copy counts and detached, locked, prunable, dirty, unchecked, and missing worktrees have a bounded inspector presentation and exact reveal guard. PR history has an explicit bounded listing plus rotating exact-tip lookup. Git detection and guided setup are implemented; the actual Apple installation still needs a clean-Mac test.
2. Finish interaction details: broader keyboard/VoiceOver and packaged-app checks, useful empty/error states, and broader performance verification. The first-run path now has a keyboard skip control, named main landmark, one page heading, focus after sidebar/workspace changes, and announced Git setup progress. Durable project/view positions, startup recovery, synchronized inventory scrolling, full-list keyboard navigation, a task-based Settings hub, and a 1,000-branch browser fixture are implemented. Browser reopen and native process restart checks verify restoration; manual VoiceOver and broader release checks remain. Evidence-bound review choices, accurate attention counts, paginated findings, and atomic monitoring removal are implemented; broader automated UI coverage remains.
3. Finish the Codex connection: destination-screen verification and wider supported-version testing. Opening is implemented with strict IDs, current association checks, accessible summaries, missing-title handling, and bounded user feedback. The packaged Mac inspector has handed current and archived associations to the registered Codex protocol handler; inspection of the final Codex screen remains blocked in this environment. Account/usage reading, read-only index discovery, version gating, multiple task associations, provenance, pagination bounds, and disconnect behavior are implemented.
4. Add relevant service, UI, restart, and packaged integration checks; review correctness/security against this full contract.
5. Run the implemented arm64/x64 draft-release pipeline with the registered GitHub App and Apple credentials. Complete clean-machine installation checks, a manual VoiceOver onboarding walkthrough, and final public release review.

The automatic advisor remains a post-release experiment. It must meet the separate execution gate in [ADVISOR.md](ADVISOR.md) before any future opt-in model runner is connected. Its unfinished state does not block the handoff-based first release.

No release is complete until every product-contract requirement has direct evidence. A green build or a working fictional demo alone is insufficient.
