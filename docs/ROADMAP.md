# First release: scope and acceptance

The goal is a polished, simple, open-source Mac desktop app that explains where coding-agent work lives and how it relates to develop/dev/main/master, even across hundreds of branches. The user expanded the scope to automatic projects, multiple coding agents, and company workspaces with GitHub plus opted-in local work. This scope must not be reduced to the existing demo or local-only prototype. See [team workspaces](TEAM_WORKSPACES.md).

## Product contract

- Electron desktop application for Apple Silicon and Intel, with a signed/notarized drag-to-Applications release.
- Local Git repositories and their worktrees, plus published GitHub branches and pull requests. Team workspaces must also include unpublished local work voluntarily shared by teammates' connected devices. Unpublished cloud tasks need an explicit supported source; do not imply they are visible by default.
- Discover saved coding-tool projects automatically, provide search across all projects, and allow removal with persistent exclusions that prevent automatic re-addition.
- Support multiple coding tools with evidence-based icons and optional model identity. Codex, Claude Code, Grok integrations, and extensible provider adapters are required; unknown or unsupported sources must be labeled accurately.
- Add personal/team separation, people/project/agent filters, PR and review alerts, an optional open-source shared service, authenticated device pairing, and explicit project sharing. Verify access isolation, revocation, unsharing, stale sources, and preservation of personal data across at least two real member devices.
- Dark graphite interface with workspace overview, grouped map, expandable groups, searchable/virtualized inventory, focused inspector, activity, and an evidence-backed review inbox. The demo contains fictional data only.
- Automatic local updates and periodic remote refresh, with source provenance, freshness, partial results, and offline state visible.
- Optional Codex integration through an installed, signed-in client. Link tasks using explicit evidence; distinguish verified links from possible associations. Core Git inspection must work without Codex or AI.
- AI may identify forgotten work, possible cleanup candidates, integration gaps, or useful next steps. Every finding links to evidence and states uncertainty.
- Automatic analysis: at most six runs per day globally, at least 30 minutes apart, at most 20 findings per run, approximately 16k input tokens, two-minute timeout. Honor account limits; never redeem credits automatically.
- Only metadata and accessible task summaries enter automatic analysis. Diffs require an explicit user action. Repository content and task text are untrusted data, never tool instructions.
- Read-only v1. Suggestions do not execute merge, rebase, push, deletion, cleanup, or worktree removal. Opening folders, tasks, and PRs is allowed.
- MIT, modular code, no repeated business logic, meaningful tests, second-pass review, and a PR to develop.

Native fictional checks verify automatic commit updates, actual process restarts, offline withdrawal recovery, search, and disconnection. Broader native checks, GitHub organization membership synchronization and live acceptance, remote/cloud agent activity, and real two-device verification remain unfinished.

## Remaining implementation and release work

The latest requested work is tracked in `docs/TEAM_WORKSPACES.md`. The team browser puts a bounded, prioritized company queue ahead of the full inventory. It combines current failing checks, review requests, quiet drafts, exact merged-branch copies, local-only branches, and apparently forgotten shared work into one finding per PR or branch. It ranks work for the signed-in member and persists private snooze, dismiss, restore, and bulk choices against evidence revisions. Local rows open the exact person/project/device/branch in `Live & local`. PRs remain visible independently of remote-branch presence, exact deleted-branch associations are preserved, and open PRs have their own listing. Bounded exact-commit lookup now recovers older closed or merged PRs that fall outside the recent listing.

1. Finish source semantics: combined native verification, source freshness, and watch/restart behavior. Current work is promoted consistently on the all-project overview and project map, with coding-tool identity and compact development/stable target status. Standard targets, a verified symbolic remote-default fallback, and an explicit no-target map/inventory/inspector state are implemented. Branch-copy counts and detached, locked, prunable, dirty, unchecked, and missing worktrees have a bounded inspector presentation and exact reveal guard. PR history has an explicit bounded listing plus rotating exact-tip lookup. Git detection and guided setup are implemented; the actual Apple installation still needs a clean-Mac test.
2. Finish interaction details: broader keyboard/VoiceOver and packaged-app checks, useful empty/error states, and broader performance verification. Durable project/view positions, startup recovery, synchronized inventory scrolling, full-list keyboard navigation, and a 1,000-branch browser fixture are implemented. Browser reopen and native process restart checks verify restoration; broader release checks remain. Evidence-bound review choices, accurate attention counts, paginated findings, and atomic monitoring removal are implemented; broader automated UI coverage remains.
3. Finish the Codex connection: accessible summaries, end-to-end verification of task destinations (including archived tasks), useful handling of missing task titles/metadata, and wider supported-version testing. Opening is implemented with strict IDs, current association checks, and user feedback; the Mac protocol handoff is tested, while destination-screen and full inspector-to-real-task checks remain pending. Account/usage reading, read-only index discovery, version gating, multiple task associations, provenance, pagination bounds, and disconnect behavior are implemented.
4. Finish the optional advisor: establish the actual model boundary, connect the tested budget/data/validation modules to a bounded runner, persist review coverage, add opt-in scheduling and explicit diff permission, integrate findings with snooze/dismissal, and verify failures/offline/restarts. The current local probe still finds injected capabilities and extra context. Verify that no repository-changing or external-action tools can run before enabling AI.
5. Add relevant service, UI, restart, and packaged integration checks; review correctness/security against this full contract.
6. Build and verify both Mac architectures. Complete signing/notarization, privacy and connection documentation, accessible onboarding, CI, third-party notices, and a reproducible public release.

No release is complete until every product-contract requirement has direct evidence. A green build or a working fictional demo alone is insufficient.
